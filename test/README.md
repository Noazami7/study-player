# test/

再生まわりと画面の確かめ。どれも合成したデータだけを使う（動画・字幕・訳の実データは入れない）。

## invariants.mjs ― 再生まわりの不変条件（Node と jsdom）

index.html の `<script>` を jsdom の上でそのまま動かし、`<video>` だけを Chromium の挙動を写した偽物に差し替える。
操作のたびに、ページの状態（色の行・止める行・巻き戻し・前回位置の保存）を、誰がシークしたかを知っているモデルの期待と突き合わせる。

```bash
(cd test && npm install)                      # 初回だけ（jsdom。node_modules は git に入れない）
node test/invariants.mjs                      # 作業ツリー: 症状のシナリオ 21 本＋ランダム操作 76,800 手（2〜3 分）
node test/invariants.mjs --no-scenarios --seeds 25..48 --busy 0.3   # イベントが遅れがちな時（X8 の経路を踏みやすい）
node test/invariants.mjs --rev 138a326        # 変更前の版（陰性対照）。症状と違反が出て終了コード 1 になるのが正しい
node test/invariants.mjs --rev 138a326 --no-scenarios --codes INV1,INV2,INV3 --keep-going   # INV1〜3 だけを数える
node test/invariants.mjs --mutants            # わざと壊した 23 版。reseek-same-target 以外は「検出」、reseek-same-target は「検出なし」が正しい
```

- 違反が出たら、その回だけを `--seeds 30..30 --data clean --trace --shrink` のように回すと、直前の経過と最小の手順が出る
- 見る条件（INV1〜3 はページの状態どうしが常に満たすべき条件、M1〜M9 はモデルとの突き合わせ）とオプションは invariants.mjs の冒頭にある
- `--mutants` は、土台の版でランダム操作の違反が出ていると、変異で新しく出た違反が見分けにくくなる（同じ seed の最初の違反が重なる）。
  土台の版を直してから回すか、`--html` で直した写しを土台に渡す
- X8〜X11 は、このハーネスで見つけて直したもの。X8 はシークの完了から seeked が届くまでの間に「1行ずつ」が止めた時の色の取り違え、
  X9 は次の行が今の行の終わりより前に始まる（重なる）時の色の行き来、X10 は前の行の中に収まった短い行で ▶ を 2 回押すこと、
  X11 は動画が進んだまま rAF だけが止まった後に古い行で止めること
- モデルは、1行ずつの間は色を止める行より先へ進めない・止めた後は止める点を過ぎた行を飛ばす・止める点を LATE 秒（0.5）以上
  過ぎてから来た tick では止めずに時刻から引き直す（止まっている時の tick でも。止まっている時の tick は止めない）、を仕様として持つ。
  重なる行と入れ子の行は real のデータにだけある
- 写しているのは Chromium の seeking の届き方だけ。WebKit（iPhone）の届き方は写していない。rAF だけが止まる場合は X11 で
  作っているが、iPhone の全画面・ピクチャインピクチャで実際に止まるかは確かめていない
- X12〜X17 は、「一覧」の確かめ・「続きから」の案内・rAF が止まる場合（全画面など）の経路。X12 は「一覧」の確かめで迷って
  キャンセル（迷っている間はページのスクリプトが止まり、止めていなければ動画だけが進む。ページは確かめの前に動画を止め、
  キャンセルで再生に戻す）、X13 は「続きから」の案内が出ている時に動画の ▶ で頭から見始める場合（案内が残り、「続きから」で
  前回の行へ戻れる。行のタップ・前・次・もう一度・続きから で見始めると消える）、X14 は rAF だけが止まって行の終わりの後の隙間で
  戻る場合（LATE の引き直し）、X15 は行をタップした直後に rAF が止まり、その行の止める点を少し過ぎて戻る場合（止める処理が
  巻き戻しの印を消す）、X16 は rAF が止まっている間に一時停止した場合（pause でも色を止めた時刻の行へ合わせる）、X17 はその
  「1行ずつ」オン版（色が止める行で頭打ちになるので、止める点を LATE 以上過ぎてから一時停止した時は止める行も時刻から引き直す。
  LATE 未満なら止めるはずだった行のまま）。X15〜X17 は変更前の版（138a326）では落ちる
- 変異の後ろの 7 版（back-no-pause・back-cancel-no-resume・play-hides-info・playFrom-keeps-info・stop-keeps-hold・pause-no-tick・
  paused-no-late-recalc）は、X12・X13・X15・X16・X17 の直しを 1 つずつ外したもの
- ランダム操作には「一覧」の確かめ（答えと迷う時間）と、再生中に rAF だけが止まる場合（その間に一時停止することもある）が入っている。
  確かめは M8 で見る（動画を読み込んでいる時だけ 1 回出る・確かめの間は動画が止まっている・キャンセルしたら一覧へ戻らず、押す前に
  再生していれば再生に戻る）。「続きから」の案内は M9 で見る（行・前・次・もう一度・続きから で見始めるまで残る）。
  止まっていた間はページが止める判定をできないので、「1行ずつ」の停止の遅れは戻った時刻か再生を始めた時刻から数え、
  戻ってから次の操作までに画面の書き換えを 1 回入れる
- 一時停止した時に色を止めた時刻の行へ合わせるか（pause で tick と同じ処理をするか）は、rAF が回っていれば最後の tick と 1 フレームしか
  違わないので、モデルはどちらも認める。rAF が止まっている間の一時停止だけは、合わせていることを求める（今の版は pause でいつも合わせる）。
  「1行ずつ」の時は、止める点を LATE 以上過ぎていれば止める行も引き直して合わせることを求める
- 確かめのダイアログの間も動画が進むことは、確かめの前に止めない版で webkit-check.py の s7 を回して WebKit（WPE）について確かめた
  （3 秒迷うと 3.0〜3.7 秒進んだ）。iPhone では確かめていない
- ページの `<script>` の末尾の `})();` の直前に、状態を読む口を差し込んで動かす。末尾の形や変数名（cur・holdUntil・stopIdx・stoppedAt・step・hasVideo）を変えたら、ここも直す

## playback-sim.mjs ― 再生まわりの再現試験（Chromium と WebKit の 2 通り）

```bash
node test/playback-sim.mjs [--fuzz 手数] [--seed 数] [--trace] [index.html のパス ...]
```

- WebKit の型は、同じ時刻へのシークのし直し（invariants.mjs の変異 reseek-same-target）を見つける。invariants.mjs の X8〜X17 の
  経路（重なる行・入れ子の行・rAF が止まる場合）は入っていない

## webkit-check.py ― 再生まわりを実際の WebKit の `<video>` で確かめる（Playwright）

```bash
uv run test/webkit-check.py --setup           # 初回だけ（WebKit と足りないライブラリを sudo なしで用意する）
uv run test/webkit-check.py                   # 合成した動画と合成した字幕
```

用意の置き場は既定で `~/.cache/study-player-webkit`。別の所に用意した時は、確かめる時も同じ `--webkit` を渡す。
`--only s7` は「一覧」の確かめを開いたまま迷ってキャンセルする場面だけを回す（確かめが出た時に動画が止まっているかと、押す前から
閉じた後までに動画が進んだ秒数も出す）。

## ui-check.py ― 画面の確かめ（ヘッドレス Chromium）

```bash
uv run test/ui-check.py                       # 合成した動画（ffmpeg の testsrc）と合成した字幕
```

手元の動画と字幕データで回す時は `--video` `--data` `--work` を渡す（元のファイルは変えず、写しを `--work` に作る。
解説（x）の入った字幕データでも、元の解説は外し、背の高い行を中心に選んだ 5 行に偽の解説を付けて確かめる）。

webkit-check.py と ui-check.py の配信は、既定で空いている番号を使う（`--port` で決めることもできる）。決めた番号で別の配信が
動いていたり、返ってきた index.html が `--root` のものと違ったりしたら、別の版を測らないように止まる。
